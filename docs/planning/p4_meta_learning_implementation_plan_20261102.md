## 一、研究目标与不可混淆的阶段

以固定 Mach 2.02、12维升力面设计问题为未来工程应用接口，先验证元学习对**响应代理初始参数**的作用，再将适应后代理引入受约束 BO 的初始化策略。路线 A 在本阶段**不学习采集函数或搜索策略本身**（那属于以后路线 B）；P4 也不声称已经完成真实飞机油耗的物理优化。

明确区分三个层级：
1. **P4-CODE**：结构、单元测试、合成任务元训练/快速适应、离线 BO/DE 对照。当前批准。
2. **P4-REAL-LF**：RCAIDE 或 VSPAERO 真实空气动力学/Mission 新调用。仅在负责人单独批准计算预算和可信度使用范围后允许。
3. **P4-MULTIFIDELITY-REAL**：真实 HF 与 LF 混合优化。须有可用的保真度配对与相容的气动/阻力口径，不能由算法代码测试替代。

## 二、问题、数据、任务定义

- 保留 `configs/design_space_12d_lifting_surfaces.yaml` 的 W01–W10 + V01–V02 12维变量顺序，机身 F01–F03 固定，仍将 `bounds_status=provisional` 如实标注。
- 固定巡航任务：Mach 2.02，18 288 m、3 028 020 m、136 000 kg 起始质量；目标为 `fuel_burn_kg`、约束延续已有十项 `g<=0` 合同。以上是**接口合同**而非物理可信性声明。
- 现有160个 P3 DOE 是**旧15维纯几何无标签候选**，不可当作12维已标注油耗训练样本；归档10个 Mission 结果均为旧任务、虽10条`VALID`但仅5条`feasible`，数量不足以支持现实跨任务元训练结论。未经验证的 VSPAERO、面积律候选禁止作为有效航空标签。
- 元学习需要**任务分布**。第一版任务族由有解析最优解/目标的合成函数构造（例如可控参数化12维二次函数、仿真低/高保真函数及约束），元训练与目标固定工况的航空任务证据严格分开。未来 Mach2.0–2.5/高度/巡航任务迁移另列数据里程碑，不能把单一 Mach2.02 的重复采样当成多个独立任务。
- 每条样本必须包含 `task_id`、`fidelity`、`evaluator_id`、`design_set`、`config_hash`、`objective/constraints/status`、`source_kind`（`synthetic`/`archived_real_lf`/`validated_real_lf`/`validated_real_hf`）、`physics_validation_status`、`git_sha`、`seed` 和 `physical_call_count`。所有无效、异常和不收敛结果的 objective 为 null。

## 三、核心代码模块与验收条目

1. `meta_learning/task_family.py`：支持显式任务上下文、固定12维输入归一化、可重复合成任务采样和独立的目标函数/约束。
2. `meta_learning/data_contract.py`：支持集/查询集划分（support/query disjoint）、按任务身份分 train/validation/test，禁止同一任务跨集合泄漏；避免用待评目标的查询标签做快速适应。
3. `meta_learning/surrogate.py`：前向预测均值与明确的损失目标，必要时附带不确定度接口；不把简单回归 RMSE 自动解释为可靠不确定度。
4. `meta_learning/maml.py`：MAML-A 内循环适应与外循环元更新，参数初始化可复现；优先实现和测试小型一阶/可微版本，随后再评估二阶实现的梯度正确性与资源成本。必须有基于有限差分的小模型梯度检查。
5. `meta_learning/adaptation.py`：给定 K-shot 支持集，适应并输出测试集预测；记录每步损失、步骤数与预算。保留零样本、少样本和从头训练基线。
6. `optimization/meta_bo_initialization.py`：将元学习得到的响应代理初始化信息传入现有受约束 BO，保留 GP/EI 与 DE 基线代码，记录普通 BO / 随机初始化 / 预训练微调 / MAML 初始化的等预算对照。不得私自切换为路线 B 的采集策略学习。
7. `meta_learning/offline_runner.py` 与测试：在合成任务上产生每次训练、适应、BO候选、约束检查的可追溯 JSON/CSV/PNG；`physical_call_count=0`，绝不能让离线测试意外导入真实 RCAIDE Mission 求解入口。
8. 报告和脚本必须能在独立干净工作树稳定运行，旧P4 BO/DE和历史P1–P3提交/配置不改写。

模块名称为建议，A1 可以在独立审阅后调整，但必须保持清晰的接口与审计语义。

## 四、可检验的离线试验矩阵

- 任务集至少区分元训练、验证、从未见过的目标测试任务；从参数配置和随机种子复现每个任务。
- 对比**随机初始化、普通监督预训练后微调、MAML-A 快速适应**，在 K=0/1/5/10 或按可解释样本数分组，画任务级和均值±离散度的 MAE/RMSE 曲线；使用同一目标查询集和相同训练预算，附消融说明。
- 在合成的约束12维优化上，以同一 `true_evaluation_budget` 对比 DE、普通约束 BO、MAML 初始化的约束 BO；使用相同算法随机种子集、初始候选数、失败处理、可行性判断与缓存规则。
- 记录首次可行评价序号、最优可行值/已知解析最优差、运行时间、实际求解请求、缓存命中和约束违反率；若元学习没有改进，应忠实报告而不是修改基线。
- 这些结果**只证明合成任务上的算法机制**，不得与 Mach2.02 真实油耗优化混称。

## 五、同步 VSPAERO 7.2.2 验证（归 Issue #4，不占 P4 算法预算）

基线证据：3.55.0 已侧装、VSPAERO7.2.2 能生成 Thin/Thick `.vspgeom` 与 setup，但 setup 中 `ReCref=1e7、Vinf=100、Rho=0.002377` 仍为默认值，而真实冻结工况为 `ReCref≈8.9397e7、Vinf≈596.0374m/s、Rho≈0.115317834kg/m³`。

先修正版次兼容、全部来流参数注入与回读断言、模板`=`约束、setup returncode、polar 完整性与波阻正负合理性检查；A5 验证后才能计费启动 VSPAERO。真实实验只可在 Issue #4 新的**单类明确授权**内运行，报告旧VSPAERO6.2.0与新版7.2.2相同参考量下的 CL/CDi/CD/Cm、面元密度、收敛与失败原因。即使新版仍失败，算法开发依然可按P4-CODE继续，但不能把未验证真实气动标签用于训练。
